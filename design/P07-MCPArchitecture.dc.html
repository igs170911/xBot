說明畫板 · PRD §22 MCP 優先的後端

XBot MCP：每個人、每個代理都走同一扇門

後端的每個功能都是一個 MCP 工具。網頁、手機、桌面 App、外部代理（Claude Code、Codex、Cursor、另一台 XBot）和 Bot 自己，都呼叫同一組操作；權限、限制、預算與核准只寫一次，誰來都一樣。

介面能做的事，MCP 都能做；沒有隱藏功能。規格卡上每個按鈕都對得到一個工具名稱。

名稱與版本固定

xbot.<領域>.<動作>xbot.bots.createxbot.chat.sendxbot.routines.run_nowxbot.hosts.remove
整組版本 xbot.v1不相容才出 v2，舊版至少留一個大版本

會改東西的工具都要帶 request_id（重送不重做），也都支援 dry_run（只回傳會發生什麼）。

錯誤固定格式

{
  "code": "needs_approval",
  "message": "刪除 Bot 要你核准，已送到待我處理",
  "retryable": false,
  "needs_approval_id": "apv_51"
}
權限不足超過限制 §18超預算 §6.13等你核准

message 一律白話中文；都回明確代碼，不丟 HTTP 例外。retryable 告訴代理要不要重試。

request_id 與 dry_run：先看會發生什麼

代理送出
{
  "tool": "xbot.bots.create",
  "request_id": "cc-1017-0942-01",
  "dry_run": true,
  "input": {
    "name": "客服小幫手",
    "does": "回覆蝦皮買家的常見問題"
  }
}
XBot 回覆（什麼都還沒做）
{
  "dry_run": true,
  "risk": "safe",
  "would": [
    "建立 Bot「客服小幫手」，權限：先問我",
    "第一次收到工作才開電腦",
    "今天還能再建 2 個（每 24 小時 3 個）"
  ],
  "needs_approval": false
}

拿掉 dry_run 再送一次就真的建立。網路斷了重送同一個 request_id，會拿到第一次的結果，不會建出兩個 Bot。

例子：Claude Code 請小秘刪掉一個 Bot

1Claude Code · 請小秘把舊客服 Bot 收掉xbot.chat.send {"bot": "小秘", "text": "舊客服不用了，刪掉"}已送出
2Claude Code · 等這件事做完或需要人xbot.chat.wait_until_settledneeds_approval
3Claude Code · 拿 needs_approval_id 等你決定xbot.approvals.wait {"id": "apv_51"}等待中
4你 · 在待我處理按「允許這次」（手機、通知都能按）刪除只能你本人
5XBot · 刪除舊客服，回傳結果給 Claude Code，記進稽核approvals.wait → {"decision": "allowed"}完成
