**核心功能**:

  - `work`: 實際工作 → 開電腦執行完整流程
  
- **即時確認**: 複雜任務先回應確認訊息
  - 自動檢測多步驟任務（「然後」「第一」等關鍵字）
  - 根據工作類型生成對應確認語（「好的，我來查一下」）
  - 簡短任務直接開始，不額外確認

## 技術亮點

### 1. 解耦設計
使用 `Decider` 介面而非直接依賴具體實作：
```go
type Decider interface {
    Decide(ctx context.Context, a judge.Ask) (judge.Decision, error)
}
```
- 測試時可用 mock
- 可替換不同的快判實作
- 職責分離清晰

### 2. 智能確認邏輯
```go
func (r *Router) shouldAck(text string) bool {
    // 檢測多步驟關鍵字
    stepIndicators := []string{"然後", "接著", "第一", ...}
    for _, ind := range stepIndicators {
        if strings.Contains(text, ind) {
            return true
        }
    }
    // 很長的訊息也需要確認
    if len([]rune(text)) > 100 {
        return true
    }
    return false
}
```

### 3. 向下相容
- 沒有快判服務時回退到完整流程
- 不破壞現有行為
- 可以逐步啟用新功能

## 設計決策

### 為什麼確認訊息用固定模板？
- **快速**: 即時回應不能等模型生成
- **可靠**: 固定語句不會出錯
- **簡單**: 不需要額外的模型呼叫
- **未來**: 可以升級為快判模型生成個性化確認

### 為什麼工具步驟要摺疊？
- **減少噪音**: 使用者關心結果，不是過程
- **里程碑式**: 只顯示重要進展
- **可選展開**: 需要時仍可查看細節
- **視覺清爽**: 大幅改善聊天體驗

### 為什麼側欄要簡化？
- **Chat-First**: 聊天是核心，側欄只是輔助
- **專注**: 減少視覺干擾
- **空間**: 給聊天區更多空間
- **現代**: 符合現代聊天應用設計趨勢
