# 連接應用程式

讓 Bot 用 GitHub、Notion、Linear 這類服務的工具（都是 MCP 服務）。在左邊「連接應用程式」。

## 連一個

目錄裡有 60 多個常用的服務，常用的在前。點一個，依它的驗證方式：

| 驗證方式 | 怎麼連 |
|---|---|
| 不用登入 | 按了就連好 |
| 要金鑰 | 貼上金鑰 |
| 要登入（OAuth） | 打開登入頁，在服務那邊按允許。回不到 XBot 時，把網址列的網址貼回來完成 |

- 金鑰和登入權杖由 XBot 保管，**不會進 Bot 的電腦**。Bot 呼叫這些工具時經 XBot 轉送。
- 連好後預設**所有 Bot** 都能用、工具全開。可以改成只給某幾個 Bot，或關掉某些工具。
- 「測試」確認連得上；權杖過期時會請你「重新登入」。
- 中斷連接要你允許。

Bot 需要某個服務時，會發一張「連接應用程式」卡到「待我處理」。

## 安全

- 從應用程式拿到的內容一律當成資料，不是你的命令。
- **會寫入的工具一定先問你**（例如發 issue、寄信、改文件），就算 Bot 的權限等級是「放手做」。
- Hermes 的 Bot 改了授權立刻生效（正在工作時下一個對話生效）；其他引擎的 Bot 下一個對話生效。

## 清單外的服務

「連接應用程式」→「自訂連接（MCP）」，填 MCP 網址或啟動指令：

- **遠端網址（HTTP）**：XBot 代為轉送，Token 不進 Bot 的電腦。
- **本機程式（指令）**：在 Bot 的電腦裡執行：你填的環境變數（例如金鑰）會寫進有授權的 Bot 電腦裡一個只有 Bot 讀得到的檔案（權限 0400）。這是「金鑰不進 Bot 電腦」規則的例外，只加你信任的服務，並只授權給需要的 Bot。

## 網站登入

Bot 在自己電腦的瀏覽器登入網站後，登入狀態會保留。「連接應用程式 → 網站登入」可以：

- 看每個 Bot 登入了哪些網站（只顯示網站名稱和 cookie 數，看不到登入資料本身）。
- **移除**某些網站的登入（要你允許）。
- **分享給其他 Bot**：把選定網站的登入狀態複製過去，對方就不用再登入（對方原本的登入會被取代，密碼不會被看到）。要你允許，10 分鐘內可以復原。

## 還沒有的

- Google（Gmail、Drive、日曆）還沒放進目錄，等決定要用哪個官方 MCP。
- 密碼庫、一次性驗證碼（TOTP）還沒做。
